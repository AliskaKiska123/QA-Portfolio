# План тестирования интернет-магазина SauceDemo

## 1. Общая информация

- **Проект:** QA Portfolio - тестирование интернет-магазина
- **Приложение:** SauceDemo
- **Тип тестирования:** Ручное тестирование
- **Объект тестирования:** Веб-приложение интернет-магазина SauceDemo

## 2. Цель тестирования

Проверить основные пользовательские сценарии интернет-магазина, оценить корректность работы его функциональности и выявить дефекты интерфейса и обработки пользовательских данных.

## 3. Область тестирования

В рамках проекта проверяются следующие функциональные области:

- **Авторизация:** вход в систему с корректными и некорректными данными, обработка пустых полей.
- **Каталог товаров:** отображение товаров, названий и цен, работа сортировки.
- **Корзина:** добавление и удаление товаров, отображение состава и стоимости заказа, сохранение содержимого при обновлении страницы.
- **Оформление заказа:** заполнение обязательных полей, проверка валидации, переход между этапами оформления.
- **Расчёт стоимости:** проверка промежуточной суммы, налога и итоговой стоимости.
- **Подтверждение заказа:** завершение оформления, отображение страницы подтверждения, возврат в каталог.
- **Формирование PDF:** проверка содержимого и корректности отображения данных в сформированном документе.

## 4. Виды тестирования

В рамках проекта применяются следующие виды тестирования:

- **Функциональное тестирование** - проверка работы основных функций приложения.
- **Исследовательское тестирование** - изучение приложения без заранее заданного полного набора тестовых сценариев.
- **Позитивное тестирование** - проверка работы приложения с корректными данными.
- **Негативное тестирование** - проверка реакции приложения на некорректные, пустые и нестандартные значения.
- **Тестирование пользовательского интерфейса** - проверка отображения элементов и информации.

Дополнительно выполнялось повторное тестирование обнаруженных дефектов для подтверждения их воспроизводимости.

## 5. Подход к тестированию

Тестирование проводится вручную с использованием пользовательского интерфейса приложения.

Основные методы:

- Проверка основных пользовательских сценариев.
- Проверка граничных и нестандартных значений.
- Проверка обязательных полей и сообщений валидации.
- Сравнение фактических результатов с ожидаемыми.
- Повторное выполнение сценариев для подтверждения обнаруженных дефектов.

Обнаруженные дефекты фиксируются в отдельных баг-репортах с указанием шагов воспроизведения, ожидаемого и фактического результатов, серьёзности и приоритета.

## 6. Тестовые данные

Для проверки используются:

- Тестовые учётные записи, предоставленные приложением.
- Данные для входа с корректными и некорректными значениями.
- Товары из каталога приложения.
- Различные комбинации товаров для проверки расчётов.
- Данные для заполнения формы оформления заказа: латинские и кириллические символы, пробелы, цифры и специальные символы.

## 7. Критерии завершения тестирования

Тестирование считается завершённым в рамках данного проекта, когда:

- Проверены основные пользовательские сценарии приложения.
- Выполнены проверки основных функциональных областей.
- Обнаруженные и подтверждённые дефекты оформлены в виде баг-репортов.
- Результаты тестирования задокументированы.
- Подготовлен итоговый отчёт о тестировании.

## 8. Ограничения тестирования

- Тестирование проводится на демонстрационном веб-приложении SauceDemo.
- Внутренняя реализация приложения и исходный код не анализируются.
- Проверка проводится вручную через пользовательский интерфейс.
- Отдельная проверка API и автоматизированное тестирование в рамках данного этапа не выполняются.
- Полные требования к приложению отсутствуют, поэтому ожидаемое поведение в отдельных нестандартных сценариях оценивается исходя из логики пользовательских операций.
